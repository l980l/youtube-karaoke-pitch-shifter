# 세션 인수인계 — 프로젝트 파악 및 개선 1차

> [!note] 후속: [[2026-11-01-개선-2차-v1.2.0]] 에서 남은 작업 1~6 완료

## 프로젝트 개요
YouTube 노래방 키 조절 크롬 확장 (MV3, repo `l980l/youtube-karaoke-pitch-shifter`, Chrome 웹 스토어 공개).
- `content/pitch-shifter.js`: Web Audio 그래프 (입력 → 보컬컷(L-R+저역) → bypass / 피치경로 → compressor → outputGain)
- `content/pitch-worklet.js`: STFT phase vocoder AudioWorklet (2048/512, 분수 bin 분배). 실패 시 delay-line(Jungle) 엔진으로 폴백
- `content/karaoke-ui.js`: 플레이어 오버레이 리모콘·OSD·페이지 단축키, `popup/`: 팝업 리모콘·단축키 설정, `background/`: chrome.commands
- 워크스페이스의 `wolfeel/`, `inconnu/` 폴더는 같은 저장소의 이전 브랜치 worktree

## 이번 세션에서 한 일
- `tests/pitch-worklet.test.mjs` 추가 (`node --test tests/*.test.mjs`): 워크릿을 Node에서 오프라인 실행해 음정·레벨 측정
- 단축키 매칭에 metaKey 비교 추가 (Cmd+[ 뒤로가기가 '[' 키내림으로 가로채이던 버그), 입력창 판별을 isContentEditable/composedPath 기반으로 변경

## 확정된 것
- 워크릿 음정 정확도는 정상: -12~+12 전 구간 5 cent 이내
- **레벨 손실 버그 확인**: 키 변경 시 출력 레벨 -3 ~ -24 dB (‑5키 -24dB, +4키 -9dB). 피치 경로가 원음보다 작게 들림

## 남은 작업 (우선순위순)
1. 워크릿 레벨 손실 수정 — 여러 source bin이 한 target bin으로 모일 때 위상 상쇄 추정 (> [!question] 미확인, 원인 검증 필요). 테스트 통과가 기준
2. 볼륨 부스트를 compressor 뒤→앞으로 이동(현재 순서로는 200% 시 클리핑), OFF/중립 상태에서 compressor를 우회하는 진짜 bypass
3. 영상 요소 교체 시 이전 오디오 그래프 해제 (중복 연결·누수), MutationObserver 스로틀
4. YouTube 자체 속도 변경(ratechange)과 템포 상태 동기화, 키 0일 때 워크릿 연산 중단(CPU)
5. 저장된 설정 shortcuts 딥머지(구버전 설정에서 신규 액션 누락), popup/content 기본설정 중복 제거
6. 기능: 곡(videoId)별 키 기억, manifest 1.0.1 ↔ README 1.1.0 버전 불일치 정리

## 주의
- 워크릿 수정 시 반드시 `tests/pitch-worklet.test.mjs`로 음정(cent)과 레벨(dB)을 함께 검증할 것
