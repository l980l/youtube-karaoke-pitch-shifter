# 오디오 그래프 구조

## Summary
`content/pitch-shifter.js`가 YouTube `<video>`마다 구성하는 Web Audio 그래프 (v1.2.0).

## 원리
```
source ─► directGain ─────────────────────────────────► destination   (true bypass)
   └─► inputGain ─► [보컬컷] ─► vocalOut ─┬─► bypassGain ───────────┐
                                          └─► worklet ─► pitchGain ─► toneFilter ─┤
                     destination ◄─ processedGain ◄─ limiter ◄─ volumeGain ◄─ mixBus
```
- **neutral** = OFF 또는 (키 0 + 보컬컷 OFF + 볼륨 100%) → directGain=1, processedGain=0. 리미터조차 거치지 않는 원음.
- 볼륨 증폭은 리미터(-1dB, 20:1) **앞**. (1.1.x는 컴프레서 뒤에 있어 200%에서 클리핑 가능했고, -12dB/3.5:1 컴프레서가 원음 다이내믹스도 바꿨음)
- 보컬컷 = (L−R) 사이드 신호 + 140Hz 이하 저역 복원.
- 키 0/OFF면 워크릿에 `{active:false}` → 0.5초 페이드 후 FFT 연산 중단.

## 동작 과정
1. `init(video)`: 소스노드는 요소당 1회만 생성 가능 → `video.__pitchSourceNode`에 캐시.
2. 다른 `<video>`로 바뀌면 `teardownGraph()`가 노드 전부 disconnect, 이전 소스는 destination 직결로 남겨 **무음이 되지 않게** 함.
3. `ratechange` 리스너로 유튜브 자체 속도 메뉴 → tempo 상태 동기화.

## 실무 고려사항
- 워크릿 로드 실패 시 지연선(Jungle) 호환 엔진으로 폴백.
- 리미터(DynamicsCompressor)는 ~6ms lookahead가 있어 direct↔processed 크로스페이드 순간 짧은 콤필터 가능(30ms 램프).
- DynamicsCompressor는 자동 makeup gain(+0.57dB, Chrome 실측)을 더함 → `processedGain`에 `LIMITER_MAKEUP_COMPENSATION`(10^(-0.57/20))을 곱해 상쇄. 리미터 설정을 바꾸면 e2e의 "limiter path level step" 체크로 값을 다시 측정할 것.
- 같은 `<video>`의 소스노드를 다른 그래프로 옮길 때 단순 disconnect하면 그 영상은 **무음**이 된다(미디어 요소 소리는 소스노드로만 나감).

## 흔한 오해
- "OFF = 원음"은 1.1.x에서 사실이 아니었음 (컴프레서·볼륨 항상 적용).
