# 포먼트 보정(목소리 음색 유지) 미채택

## Summary
키 변경 시 목소리 음색 변화(다람쥐/굵은 목소리)를 줄이는 포먼트 보정과 스테레오 링크를 구현했으나, 오너가 **"별로 의미 없다"고 판단해 채택하지 않고 v1.2.0 방식을 유지**한다. 구현은 닫힌 PR #3(https://github.com/l980l/youtube-karaoke-pitch-shifter/pull/3)에 보존.

## Context
사용자 보고 "사람 목소리가 이상하게 들린다" → 사용자가 원인으로 **음색 변화(포먼트 이동)** 를 지목. 피치 시프트에서 하모닉과 함께 스펙트럼 윤곽까지 이동해 생기는 본질적 현상.

## 검토한 대안
| 대안 | 결과 | 채택 |
|---|---|---|
| v1.2.0 그대로 (peak-locked PV, 보정 없음) | 음색 변화 있음 | **O (오너 결정)** |
| True Envelope 포먼트 보정 + 스테레오 링크 (PR #3, v1.3.0) | 말소리 음색 오차 약 절반 감소, CPU 7%→10% | X |

## PR #3 측정치 (다시 검토할 때 참고)
- 실제 말소리(macOS Yuna) 500~3500Hz 1/3옥타브 음색 오차: −4키 3.84→1.77, +4키 3.89→2.66, −7키 4.26→1.45 dB
- 합성 모음 평균 3.45→2.19 dB. 하지만 청취 비교에서 오너가 체감 개선이 크지 않다고 판단
- 별도 발견: v1.2.0은 L/R을 독립 처리해 **가운데 보컬이 L−R로 −18.5dB 누출**(퍼짐/울림). 스테레오 링크로 < −40dB가 됐으나 함께 미채택 → **v1.2.0에 남아 있는 알려진 한계**

## 재시도 시 주의 (PR #3에서 겪은 함정)
- 일반 켑스트럼 1회 스무딩은 포먼트를 뭉갬. True Envelope 필요
- 4배 풀링 도메인에서도 켑스트럼 인덱스 n = n/sampleRate초. 리프터를 풀링 배수로 나누면 안 됨
- 기본음 아래·마지막 하모닉 위 빈 대역은 −100dB 바닥이 윤곽을 끌어내려 가짜 혹(+18dB) 생성 → 50dB 레인지 제한 + 피크 높이로 평탄 유지
- 전 대역 보정 시 치찰음('ㅅ')이 −12dB 먹먹해짐 → 3~5kHz 페이드아웃
- 순수 사인/베이스가 윤곽으로 오인돼 음량 변화 → 위 평탄 유지로 해결
- 평가는 피크 위치·스펙트럼 무게중심이 아니라 하모닉 세기 vs 원래 윤곽 RMS dB, 말소리는 1/3옥타브 LTAS로
