# 포먼트 유지(True Envelope) 및 스테레오 링크 채택

## Summary
워크릿에 True Envelope 기반 포먼트 보정(기본 켜짐, 팝업 "목소리 자연스럽게" 토글)과 L/R 공통 분석(스테레오 링크)을 넣는다.

## Context
[[키-변경-시-목소리가-다람쥐-굵은-목소리로-변함]]. 사용자가 원인 1번(음색 변화)을 지목.

## 검토한 대안
| 대안 | 장점 | 단점 | 채택 |
|---|---|---|---|
| 보정 없음 | 가장 가벼움 | 다람쥐/굵은 목소리 | X |
| 일반 켑스트럼 1회 | 단순 | 포먼트 뭉개짐, 고음에서 붕괴 | X |
| 최대값 필터 윤곽 | 단순 | 포먼트가 평평한 고원이 돼 보정 무효 | X |
| **True Envelope (4x 풀링, 512pt, 최대 8회)** | 하모닉 꼭짓점을 따라감, 정확 | CPU +4%p | O |
| 채널별 독립 처리 | 기존 | 보컬 side 누출 −18.5dB | X |
| **스테레오 링크 (파워합 스펙트럼으로 1회 결정, 양 채널 동일 적용)** | 누출 < −43dB, CPU 오히려 감소 | 지배 채널 기준 주파수 추정 | O |

## 선택 근거 (측정)
- 합성 모음(110~440Hz, F1/F2) 음색 오차: 끔 3.45dB → 켬 2.19dB, 악화 사례 0
- 실제 말소리(macOS Yuna) 500~3500Hz 1/3옥타브 오차: −4키 3.84→1.77, +4키 3.89→2.66, −7키 4.26→1.45 dB
- 사인·베이스 등 희소한 소리 음량 ±0.7dB(사인 +12키만 1.7dB)
- CPU(백색잡음 스테레오, Node): main 6.9% / 새 엔진 끔 6.0% / 켬 10.0%

## 파라미터 (content/pitch-worklet.js)
- `LIFTER_SECONDS` 1.2ms (0.8/1.0/1.25/1.5 스윕 결과), `ENVELOPE_POOL` 4, 반복 8회, 허용 2dB
- 보정 ±20dB 클램프, `FORMANT_FULL_HZ` 3000 → `FORMANT_NONE_HZ` 5000 선형 페이드
- 윤곽 하한 최대−50dB, 첫/마지막 강한 하모닉(최대−30dB 이내) 바깥은 그 피크 높이로 평탄 유지

## 되돌리는 조건
- 실사용에서 CPU 부담(저사양 기기 끊김) 보고 → 반복 횟수/풀링 상향 또는 기본값 끔
- 실제 노래에서 치찰음·숨소리가 부자연스럽다는 피드백 → FORMANT_FULL/NONE_HZ 재조정
- 듣기 비교 샘플: 저장소 밖 로컬 `listening-samples/` (커밋 안 함)
