# AGENTS.md — 이 vault의 정본 규약 (1단계 코어)

이 문서는 이 Obsidian vault에서 일하는 **모든 AI 에이전트(Claude Code, Codex, 그 외)의 단일 정본 규칙**입니다.
Claude Code는 `CLAUDE.md`를 먼저 읽지만, `CLAUDE.md`는 이 문서를 불러오는 얇은 래퍼입니다. 규칙이 충돌하면 **이 문서가 우선**합니다.

목표는 개인 메모장이 아니라, **여러 에이전트와 사람이 같은 업무 맥락을 공유하는 재현 가능한 프로세스**입니다.

---

## 1. 3계층 원칙

| 계층 | 위치 | 소유자 | 규칙 |
|---|---|---|---|
| **Raw (불변 원본)** | `AI-Sessions/raw/` | 사람 | 에이전트는 **읽기 전용**. 수정·삭제·이름변경 금지 |
| **Wiki (가공 지식)** | `AI-Sessions/wiki/` | 에이전트 | 에이전트가 생성·갱신·교차링크·정합성 유지 |
| **Schema (규약)** | `AGENTS.md`, `CLAUDE.md`, `templates/` | 사람 승인 | 사용자가 명시적으로 요청할 때만 수정 |

핵심 원칙: **지식은 누적된다.** 매번 새로 답을 만들지 말고, 한 번 정리한 문서를 갱신하고 링크를 강화합니다.
같은 사실을 두 문서에 복제하지 말고, 한 곳에 쓰고 `[[위키링크]]`로 참조하세요.

## 2. 폴더 구조 (1단계)

```text
<vault>/
├── AGENTS.md              # 정본 규약 (이 문서)
├── CLAUDE.md              # Claude Code 진입점 → AGENTS.md 불러옴
├── START_HERE.md          # 사람용 온보딩
├── index.md               # vault 카탈로그 (문서별 한 줄 요약)
├── log.md                 # 시간순 append-only 작업 로그
├── templates/             # 문서 타입별 템플릿
└── AI-Sessions/
    ├── raw/               # 불변 원본 (사람만 넣음)
    ├── conversations/     # 세션 인수인계 (handoff)
    └── wiki/
        ├── concepts/      # 반복해 쓰는 개념·용어·내부 동작
        ├── decisions/     # 의사결정 + 근거 + 결정권자 + 날짜
        └── errors/        # 실패·버그·재시도 금지 리스크
```

> 2단계에서 `sources/` `projects/` `design/` `dev-tasks/` `playbooks/` 를 추가합니다.

## 3. 문서 분류는 2축이다

**폴더는 "무슨 종류의 문서인가"(type), frontmatter의 `domain`은 "어느 업무 영역인가"입니다.**
폴더를 업무 영역으로 나누면 "이건 어디 넣지?" 문제가 계속 생기므로, 영역은 반드시 `domain` 필드로만 표현합니다.

`domain` 값은 **본인 업무에 맞게 3~5개로 정해서 아래 표를 고쳐 쓰세요.**

| `domain` | 대상 업무 |
|---|---|
| `extension` | 크롬 확장 구조 — manifest, content/popup/background, 메시징, 단축키 |
| `audio` | Web Audio DSP — 피치 시프트(phase vocoder), 보컬 컷, 볼륨/리미터 |
| `release` | 배포 — Chrome 웹 스토어, 패키징, 버전 관리 |

## 4. 명령 체계 (1단계 — 2개)

명령 키워드는 **영어로 고정**하고, 사람은 한국어 자연어로 말합니다.

| 명령 | 하는 일 | 대표 자연어 트리거 |
|---|---|---|
| `save` | 이번 작업 맥락을 위키에 저장 | "옵시디언에 저장해줘", "이거 위키에 남겨줘" |
| `reference` | 위키를 읽어 이전 맥락 복원 (별칭: `query`) | "옵시디언 참조", "위키 확인하고 시작해줘" |

**세션 시작 시 기본 동작**: 사용자가 이 vault의 업무를 요청하면, 명시하지 않아도 `reference`를 먼저 수행합니다.

### `save` 절차

1. **필터링** — 아래 5필터를 적용한다. 하나도 통과 못 하면 중단하고 이유를 한 줄로 보고한다.
2. **중복 확인** — 같은 주제 문서가 이미 있는지 찾는다. **있으면 새로 만들지 말고 갱신**한다.
3. **타입·domain 결정** — 왜 그렇게 했는가 → `decisions/`, 무엇이 실패했는가 → `errors/`, 반복해 쓸 개념 → `concepts/`.
4. **작성** — `templates/`의 해당 템플릿을 복사해 채운다. 추측은 `> [!question] 미확인` 블록으로 분리한다.
5. **링크** — 관련 기존 문서에 `[[역링크]]`를 최소 1개 건다. 고아 문서를 만들지 않는다.
6. **카탈로그·로그 갱신** — `index.md`에 한 줄 요약 등재, `log.md` 맨 아래에 한 줄 append.
7. **보고** — 아래 6절 규격대로 보고.

### `reference` 절차 (읽기 전용)

1. `index.md` 전체를 읽는다.
2. `log.md` 마지막 10~20줄을 읽는다.
3. 요청 키워드로 `AI-Sessions/wiki/`를 검색해 관련도 높은 문서 3~7개를 읽는다.
4. **핵심 맥락 / 확정된 결정 / 피해야 할 것 / 남은 액션 / 참조한 문서** 형식으로 요약한다.
5. 관련 문서가 없으면 **"위키에 관련 문서 없음"이라고 명시**한다. 지어내지 않는다.
6. 파일을 수정하지 않고, 로그도 남기지 않는다.

## 5. 저장 5필터

무분별한 저장은 맥락 오염을 만듭니다. 저장 **전에** 확인하고, **몇 번을 통과했는지 사용자에게 보고**합니다.

1. 향후 실무에 **반복해서 재사용**될 데이터인가?
2. 다른 에이전트나 동료가 **프로젝트를 이어받기 위해 반드시 읽어야** 하는가?
3. 의사결정의 **근거와 결정권자**를 나중에 추적할 필요가 있는가?
4. **실패한 방식이라 다시 시도하면 안 되는** 리스크 정보인가?
5. 팀 전체가 맞추어야 하는 **공통 규칙이나 디자인 가이드**인가?

하나도 만족하지 않으면 **저장하지 않고**, 저장하지 않은 이유를 한 줄로 설명합니다.
판단이 애매하면 저장하지 말고 사용자에게 물어봅니다. 되돌리기보다 안 만드는 쪽이 쌉니다.

## 6. 문서 포맷

```yaml
---
title: 문서 제목
type: concept | decision | error | handoff
domain: engine | study          # 3절에서 본인이 정한 값
status: draft | active | superseded | archived
created: YYYY-MM-DD
updated: 2026-11-01
owner: 결정권자                  # decision 타입 필수
tags: []
---
```

본문 기본 골격은 `Summary → Context → Details → Links`입니다.
`decision`은 `검토한 대안 / 선택 근거 / 결정권자·날짜 / 되돌리는 조건`을, `error`는 `증상 / 원인 / 해결 / 재발 방지`를 반드시 포함합니다.

### 명명 규칙

| 위치 | 파일명 |
|---|---|
| `decisions/` | `YYYY-MM-DD-슬러그.md` |
| `errors/` | 증상 기준 (예: `데디서버에서-GA가-발동하지-않음.md`) |
| `conversations/` | `YYYY-MM-DD-주제.md` |
| 나머지 | 개념 이름 그대로 |

파일명은 Obsidian 위키링크의 키입니다. **vault 전체에서 유일**해야 하며, 한 번 정하면 함부로 바꾸지 않습니다.

## 7. index.md 와 log.md 갱신 의무

- **`index.md`**: 위키 문서를 만들거나 상태를 바꾸면 **반드시** `[[링크]] — 한 줄 요약`을 추가·수정합니다. 요약 없는 링크는 등재하지 않습니다.
- **`log.md`**: `save`를 끝낼 때마다 **맨 아래에 한 줄 추가**합니다. 기존 줄은 수정·삭제하지 않습니다(append-only).

```text
- 2026-09-03 15:40 | save | ASC 소유 주체를 PlayerState로 이동한 결정 기록 | [[2026-09-03-asc-소유주체-playerstate]]
```

`reference`는 읽기만 하므로 로그를 남기지 않습니다.

## 8. 금지 사항

- `AI-Sessions/raw/` 아래 파일의 수정·삭제·이동
- API 키, 토큰, 비밀번호, 사내 기밀, 타인의 개인정보 저장
- 사용자 요청 없이 `AGENTS.md` / `CLAUDE.md` 수정
- 근거 없는 추측을 사실처럼 기록 — 불확실하면 `status: draft` + `> [!question] 미확인` 블록
- 기존 문서와 모순되는 내용을 조용히 덮어쓰기 — 양쪽을 남기고 `> [!warning] 상충` 블록으로 표시한 뒤 사용자에게 보고
- 같은 내용을 여러 문서에 복제 (링크로 대체)
